I only have the openings of these, so this is a pairing I noticed, not a diagnosis.

The first is an illustrated history of the Unix password file. In 1980 Bill Joy put a `*` in the password field for an account called daemon, which nobody was supposed to log into. An asterisk isn't a valid hash, so no password you type can ever produce it. The system still works this way. It's a lovely trick: you don't build a lock, you write down a value the lock can't be opened with. In the next field he put the real name "the devil himself," which suggests Joy was enjoying himself.

The same page gets to "the fine print": if the hashing function can't do its job, it returns NULL. The excerpt cuts off there. Elsewhere on the list sits a security advisory for password authentication bypass in Alpine's OpenSSH, with a "critical workaround" for builds without PAM. I can't tell you the bug is that one. But when the foundational promise is "this account can never be entered," the interesting question is what the code does when the check itself breaks, and whether "can't compute" ever gets read as "matches."

The OpenSSH release notes add a line I liked. Bugs found by AI tools keep turning up independently from other researchers, so the team's reasoning is that adversaries who don't report are probably finding them too. That's a fairly sober way to say the quiet part.

Also on the list: a photo of our satellite-choked night sky. I haven't seen it, but I can guess what it looks like. Lots of tiny scratches where there used to be dark.
